# ScholarEdge — Competition Demo Plan

## Target demo

Use a small collection of public research papers.

### Flow

1. Upload three papers.
2. Show processing.
3. Ask a cross-paper question.
4. Open source/page references.
5. Compare two papers.
6. Ask for a beginner-friendly explanation.
7. Generate a short quiz.
8. Demonstrate figure/screenshot understanding when that feature is implemented.
9. Show the AI provider/runtime status.
10. Show verified Snapdragon benchmark evidence when available.

## Demo principle

The demo should tell one coherent story:

```text
Read
 ↓
Understand
 ↓
Research
 ↓
Compare
 ↓
Learn
```

## What not to demo

Do not demo unstable features merely to increase feature count.

Do not show fabricated Snapdragon metrics.

Do not use confidential/private documents.

## Fallback

The application should still demonstrate its core research workflow if Snapdragon hardware access is temporarily unavailable. Snapdragon-specific claims must then be described as planned/targeted rather than verified.
